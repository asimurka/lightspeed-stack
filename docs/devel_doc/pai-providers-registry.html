PAI migration — providers registry

Lightspeed Core Stack (LCORE) · OGX removal notes · Oct 2026

After OGX removal, LCORE owns inference routing: which configured backend to use, which models it may serve, and how to build pydantic-ai wire objects for chat and embeddings, plus sentence-transformers CrossEncoder for rerank. One ProviderRegistry, one config tree (inference.providers[]), seven backends: openai, azure, vertexai, bedrock, watsonx, vllm, sentence_transformers. Drop OGX-era types ollama, vllm_rhaiis, vllm_rhel_ai (product names stay as ids on type: vllm). Bump pydantic-ai to ≥ 2.38.0 for native VLLMProvider.

1. Decision

Replace OGX’s three-level model graph (inference provider → registered_resources.models → optional allowed_models gate) with a two-level catalog:

  1. Provider — one inference.providers[] entry
  2. Models — that entry’s allowed_models (local name → vendor / Hub id, with model_type)

At boot each entry becomes one InferenceProvider (optional SDK client + cached catalog). Call sites resolve (provider_id, name) via getters on that instance — not through a second registry, and not through registry-level model getters.

Baseline:
  • One instance per config entry; catalog cached at create() — no per-request rebuild
  • Key by provider_id (not only type)
  • CatalogModelType = llm | embedding | rerank
  • One ABC for all backends — no capability interfaces / mixins. Listing filters the catalog; unsupported types are simply empty / None
  • Public ids stay LCORE names; pass only configured kwargs
Avoid: separate embedding/rerank registries · LLMCapable / similar protocols · OGX registered_resources.models · LiteLLM hop · renaming public ids to SDK names · X-OGX-Provider-Data after cutover.

2. Request contract

API How provider + model are chosen Getter
Query / streaming / Responses / A2A Query: optional provider + model, else inference.default_*. Responses / A2A: provider/model (first /). Chat defaults only — never ST. get_llm

5. Runtime architecture

inference.providers[] │ startup ▼ ProviderRegistry # map + list only get(provider_id) → InferenceProvider | None list_models(model_type?) # flatten p.get_models(...) │ ▼ InferenceProvider[E] models : tuple[CatalogModel,…] get_models(model_type?) # filter → [] if none of that type get_llm / get_embedding / get_rerank │ ▼ OpenAI · Azure · Vertex · Bedrock · Watsonx · Vllm · SentenceTransformers
Listing vs construction:
  • get_models — filter self.models. Missing type → [] (OpenAI has no rerank rows; ST has no llm rows).
  • Every backend exposes get_llm / get_embedding / get_rerank. Wrong name or catalog type → None → 404. Catalog type matches but _create_* unwired → NotImplementedError.
  • Registry has no model getters.
provider = registry.get(provider_id)
if provider is None:
    raise HTTPException(404, …)
model = provider.get_llm(name)
if model is None:
    raise HTTPException(404, …)

5.2 Unified interface

create builds the client (may be None for ST), then loads the catalog once. Discovery is async; callers never see a half-ready provider. 

class InferenceProvider(ABC, Generic[E]):
    provider_type: ClassVar[ProviderType]
    # entry, provider_id, client?, models

    @classmethod
    async def create(cls, entry: E) -> Self: ...

    def get_models(self, *, model_type: CatalogModelType | None = None) -> list[CatalogModel]:
        if model_type is None:
            return list(self.models)
        return [m for m in self.models if m.model_type == model_type]

    def get_llm(self, name: str) -> Model | None:
        if not self._accepts(name, "llm"):
            return None
        return self._create_llm(name)

    def get_embedding(self, name: str) -> EmbeddingModel | None:
        if not self._accepts(name, "embedding"):
            return None
        return self._create_embedding(name)

    def get_rerank(self, name: str) -> Any | None:
        if not self._accepts(name, "rerank"):
            return None
        return self._create_rerank(name)

    def get_model_profile(self, name: str) -> ModelProfile | None:
        if not self._accepts(name, "llm"):
            return None
        return self._resolve_profile(name)   # §7

    def _create_llm(self, name: str) -> Model:
        raise NotImplementedError

    def _create_embedding(self, name: str) -> EmbeddingModel:
        raise NotImplementedError

    def _create_rerank(self, name: str) -> Any:
        raise NotImplementedError

    @abstractmethod
    def _build_client(self) -> Any: ...
    @abstractmethod
    async def discover_models(self) -> list[CatalogModel]: ...

Catalog load (chat backends): vendor discover → ∩ allowed_models → typed CatalogModel rows. Missing allowed id → warn and omit (do not fail boot). ST: discover_models is allowed_models (no Hub list); filter is identity. Classify each row: embed vs rerank (name markers / explicit model_type). Never llm, so get_llm returns None without raising. 

@dataclass(frozen=True)
class CatalogModel:
    id: str                          # catalog name (AllowedModel.name)
    provider_resource_id: str        # wire / Hub id
    model_type: CatalogModelType
    metadata: dict[str, Any] = field(default_factory=dict)

# discover_models returns the same shape; create() caches it as self.models

5.5 Registry

class ProviderRegistry(metaclass=Singleton):
    async def initialize(self, inference: InferenceConfiguration) -> None: ...
    def get(self, provider_id: ProviderId) -> InferenceProvider[Any] | None: ...
    def list_providers(self) -> Sequence[InferenceProvider[Any]]: ...
    def list_provider_ids(self) -> list[ProviderId]: ...
    def list_models(self, *, model_type: CatalogModelType | None = None) -> list[CatalogModel]:
        out: list[CatalogModel] = []
        for p in self._providers.values():
            out.extend(p.get_models(model_type=model_type))
        return out

6.5 WatsonX

No native PAI type. Talk to watsonx.ai OpenAI-compat at {base_url}/ml/v1. LCORE owns three pieces:

  1. IBM Cloud API key → IAM bearer (not usable as Authorization as-is)
  2. default_query={"version": "…"} on the client
  3. project_id on every chat request (extra body)

Thin WatsonxProvider (name="watsonx") wrapping a prepared AsyncOpenAI — not LiteLLM. Conservative profile via get_model_profile (§7); watsonx ids are not GPT names.

IAM tokens last ~1h. Cache by API key, refresh ~60s before expiry, share one exchange across concurrent requests. This is the only backend where LCORE must manage short-lived tokens (Azure Entra / Vertex ADC / Bedrock SigV4 refresh inside their SDKs). 

IAM_TOKEN_URL = "https://iam.cloud.ibm.com/identity/token"
IAM_GRANT = "urn:ibm:params:oauth:grant-type:apikey"
SKEW_SECONDS = 60

async def exchange_iam_token(api_key: str) -> tuple[str, float]:
    async with httpx.AsyncClient() as http:
        resp = await http.post(
            IAM_TOKEN_URL,
            headers={"Content-Type": "application/x-www-form-urlencoded"},
            content=f"grant_type={IAM_GRANT}&apikey={api_key}",
            timeout=30,
        )
        resp.raise_for_status()
        data = resp.json()
        return data["access_token"], float(data.get("expiration", time.time() + 3600))


async def get_iam_token(api_key: str, cache: dict) -> str:
    cached = cache.get(api_key)
    if cached and time.time() < cached[1] - SKEW_SECONDS:
        return cached[0]
    token, expires_at = await exchange_iam_token(api_key)
    cache[api_key] = (token, expires_at)
    return token


class WatsonxIAMAuth(httpx.Auth):
    def __init__(self, api_key: str, iam_cache: dict) -> None:
        self.api_key, self.iam_cache = api_key, iam_cache

    async def async_auth_flow(self, request: httpx.Request):
        token = await get_iam_token(self.api_key, self.iam_cache)
        request.headers["Authorization"] = f"Bearer {token}"
        yield request
Preferred: build the client once in _build_client (Final[_client]). Inject Bearer per request via WatsonxIAMAuth — same idea as Azure’s token-provider. Do not rebuild the client on IAM refresh.

6.6 vLLM

OpenAI-compat remote (RHOAI, RHEL AI, RHAIIS, or any other vLLM host). Use PAI’s native pydantic_ai.providers.vllm.VLLMProvider (pydantic-ai ≥ 2.38.0) — do not invent an LCORE VllmProvider or wrap raw OpenAIProvider (that assumes GPT profiles). Product names are LCORE ids, not extra types — one VllmInferenceProvider class, one config shape. Separate deployments (different URLs) get separate ids; PAI’s Provider.name stays "vllm".

PAI already merges leading system messages by default (chat templates that reject multiples) and picks family profiles from the model id (Llama → meta, Qwen → qwen, …). Granite and other unmapped ids still need LCORE’s conservative / model_profiles_path overlay (§7). Out of default scope: Anthropic /v1/messages, llm-d fairness header, OGX /health probe. Tool calling needs the server started with --enable-auto-tool-choice and a model-specific --tool-call-parser.

7. Profiles and settings

Chat only. Call get_model_profile after a successful get_llm. Embeddings do not use ModelProfile.

model = provider.get_llm(name) profile = provider.get_model_profile(name) resolved = resolve_model_settings(profile, requested) Agent.run(..., model=model, model_settings=resolved.applied)

Merge order: DEFAULT_PROFILE → PAI provider model_profile() (for vLLM: family-aware + multi-system merge) or LCORE conservative OpenAI-compat base (WatsonX / unmapped ids) → optional model_profiles_path overlay. Resolve-then-echo rules unchanged: drop unsupported settings with warnings; 400 only for output-contract / cannot-start. Do not catch PAI UserError as a capability probe.

  • Chat: allowed_models is None → all discovered; else discovered ∩ allowed

  • Missing allowed id → warn and omit (not fail boot)
  • Public list = usable catalog, not raw vendor inventory
