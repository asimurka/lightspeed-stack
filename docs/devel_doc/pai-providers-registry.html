PAI migration — providers registry

Lightspeed Core Stack (LCORE) · OGX removal notes · Oct 2026

After OGX removal, LCORE owns inference routing: which configured backend to use, which models it may serve, and how to build an authenticated client plus a pydantic-ai Model for Query / Responses / A2A. This note is the design for that registry. Backends in scope are the six in providers.md.

1. Decision

Replace OgxProvider / OgxResponsesModel with a process-wide ProviderRegistry keyed by provider_id. At boot, each inference.providers entry becomes one InferenceProvider instance (SDK client + cached model list). A request resolves to (provider_id, bare_model_name) → Model. Env / ADC / SigV4 stay with the SDK where a first-class client already exists. LCORE owns auth glue only where the SDK does not: Azure Entra client construction, WatsonX IAM + project_id, optional Vertex credentials file.

Baseline:
  • One instance per config entry; client and catalog are Final / cached — no per-request rebuild
  • Key by provider_id (not only type) so several vLLM URLs can coexist
  • Public ids stay LCORE names (openai, azure, vertexai, …) even when the SDK’s internal name differs
  • Pass only what config sets; omitted fields leave SDK defaults
Avoid: LiteLLM as a universal hop · renaming public ids to SDK names (google-cloud, litellm) · re-implementing boto3 / ADC chains in LCORE · X-OGX-Provider-Data after cutover.

2. Request contract

Unchanged. Both APIs resolve to the same registry lookup.

API How provider + model are chosen
Query / streaming query Optional provider + model; else inference.default_*
Responses / A2A Composite model = provider/model via extract_provider_and_model_from_model_id (split on the first /)

WatsonX ids often contain slashes (meta-llama/…); Bedrock foundation ids use dots (anthropic.claude-…). The first-slash split is intentional and must stay.

3. Layers

Three objects, do not conflate them:

Layer Lives in Job
InferenceProviderEntry config (Pydantic) Operator intent: type, id, allowed_models, nested config
InferenceProvider LCORE runtime One instance per entry. Owns the SDK client, the cached catalog, build_model, get_model_profile
SDK client + wire Model pydantic-ai / vendor SDK Auth + HTTP; request shaping (Responses vs Chat vs Converse vs Gemini)

pydantic-ai itself splits Provider (authenticated client) from Model (wire protocol). LCORE’s InferenceProvider wraps both: it builds the client once, then constructs a Model per allowed name.

4.2 Entry models

Config types only. Runtime classes are §5 (*Entry vs *InferenceProvider). YAML may omit id; it defaults to type so the registry never sees None. Set id only when two entries share a type (e.g. two vLLM URLs). InferenceConfiguration rejects duplicate ids (same pattern as shields / vector-store providers) — the registry does not re-check.

5. Runtime architecture

Config describes intent. The runtime builds one authenticated client per entry, discovers models once, and hands a wire Model to the agent. Backend SDK details are §6.

inference.providers[] (InferenceProviderEntry) │ startup (once) ▼ ProviderRegistry (Singleton) provider_id → InferenceProvider │ ▼ InferenceProvider[E] # one instance for the process lifetime provider_type : ClassVar[ProviderType] provider_id : Final[ProviderId] client : Final # SDK client, built once models : tuple[…] # catalog after discover ∩ filter build_model() # wire Model for an allowed name │ six @final subclasses ▼ OpenAI / Azure / VertexAI / Bedrock / Watsonx / Vllm

Call sites are in-process. get / get_model return None when the id is unknown (bad query provider / model); the HTTP adapter maps that to 404. Do not rely on KeyError for request traffic. initialize runs once at startup; config changes mean a process restart. Do not mutate models in place.

5.2 Unified interface

Generic E so each final class sees its own entry + config type (no cast from the wide union). Subclasses implement client construction, discovery, profile, and _create_model. Catalog policy and build_model stay on the ABC.

Discovery is async (vendor HTTP), so it cannot run inside sync __init__. Use an async factory: create builds the client, then discovers and caches models. Callers never see a half-ready provider. 

E = TypeVar("E", bound=InferenceProviderEntryBase)


class InferenceProvider(ABC, Generic[E]):
    provider_type: ClassVar[ProviderType]

    def __init__(self, entry: E) -> None:
        self._entry: Final[E] = entry
        self.provider_id: Final[ProviderId] = entry.id  # always set by config
        self._client: Final[Any] = self._build_client()
        self._models: tuple[CatalogModel, ...] = ()
        self._model_ids: frozenset[str] = frozenset()

    @classmethod
    async def create(cls, entry: E) -> Self:
        """Startup path: build client, then load the model catalog once."""
        provider = cls(entry)
        await provider._load_model_catalog()
        return provider

    async def _load_model_catalog(self) -> None:
        """Discover vendor models, apply allowed_models, cache the result (§8.2)."""
        discovered = await self._discover_models_or_fallback()
        selected = self._apply_allowed_models_filter(discovered)
        catalog = self._to_catalog_models(selected)
        self._models = tuple(catalog)
        self._model_ids = frozenset(model.provider_resource_id for model in catalog)

    async def _discover_models_or_fallback(self) -> list[DiscoveredModel]:
        try:
            return await self.discover_models()
        except Exception:
            logger.exception(
                "discovery failed for provider %r; catalog will be empty",
                self.provider_id,
            )
            return []

    def _apply_allowed_models_filter(
        self, discovered: list[DiscoveredModel]
    ) -> list[DiscoveredModel]:
        if self.allowed_models is None:
            return list(discovered)  # allow all fetched
        discovered_by_id = {model.id: model for model in discovered}
        selected: list[DiscoveredModel] = []
        for model_name in self.allowed_models:
            if model_name in discovered_by_id:
                selected.append(discovered_by_id[model_name])
            else:
                logger.warning(
                    "allowed model %r not found in provider %r discovery; "
                    "omitting from catalog",
                    model_name, self.provider_id,
                )
        return selected

    def _to_catalog_models(
        self, selected: list[DiscoveredModel]
    ) -> list[CatalogModel]:
        return [
            CatalogModel(
                identifier=f"{self.provider_id}/{model.id}",
                metadata=model.metadata,
                api_model_type="llm",
                provider_id=self.provider_id,
                type="model",
                provider_resource_id=model.id,
                model_type="llm",
            )
            for model in selected
        ]

    @property
    def entry(self) -> E: ...
    @property
    def allowed_models(self) -> list[str] | None: ...  # None → all discovered
    @property
    def client(self) -> Any: ...
    @property
    def models(self) -> Sequence[CatalogModel]: ...

    @abstractmethod
    def _build_client(self) -> Any: ...
    @abstractmethod
    def get_model_profile(self, model_name: str) -> ModelProfile: ...
    @abstractmethod
    async def discover_models(self) -> list[DiscoveredModel]: ...
    @abstractmethod
    def _create_model(self, model_name: str) -> Model: ...

    def accepts_model(self, model_name: str) -> bool:
        return model_name in self._model_ids

    def build_model(self, model_name: str) -> Model:
        if model_name not in self._model_ids:
            raise KeyError(model_name)
        return self._create_model(model_name)

5.4 Singleton holder

class ProviderRegistry(metaclass=Singleton):
    def __init__(self) -> None:
        self._providers: dict[ProviderId, InferenceProvider[Any]] = {}

    async def initialize(self, inference: InferenceConfiguration) -> None:
        """Startup only: create each provider (client + catalog) from config.

        Duplicate ids are already rejected by InferenceConfiguration.
        Sequential create is enough at boot (few providers); parallel
        gather is optional if discovery latency matters.
        """
        providers: dict[ProviderId, InferenceProvider[Any]] = {}
        for entry in inference.providers:
            providers[entry.id] = await PROVIDER_CLASSES[entry.type].create(entry)
        self._providers = providers

    def get(self, provider_id: ProviderId) -> InferenceProvider[Any] | None:
        return self._providers.get(provider_id)

    def get_model(
        self, provider_id: ProviderId, model_name: str
    ) -> Model | None:
        provider = self.get(provider_id)
        if provider is None or not provider.accepts_model(model_name):
            return None
        return provider.build_model(model_name)

    def list_provider_ids(self) -> list[ProviderId]: ...
    def list_providers(self) -> Sequence[InferenceProvider[Any]]: ...
    def list_models(self, *, model_type: CatalogModelType | None = None) -> list[CatalogModel]: ...
    def list_providers_catalog(self) -> ProvidersListResponse: ...  # §8.5
registry = ProviderRegistry()
provider_id, model_name = resolve_provider_and_model(request)  # defaults applied
model = registry.get_model(provider_id, model_name)
if model is None:
    raise HTTPException(status.HTTP_404_NOT_FOUND, detail="…")

6.5 WatsonX

No native PAI type. Talk to watsonx.ai OpenAI-compat at {base_url}/ml/v1. LCORE owns three pieces:

  1. IBM Cloud API key → IAM bearer (not usable as Authorization as-is)
  2. default_query={"version": "…"} on the client
  3. project_id on every chat request (extra body)

Thin WatsonxProvider (name="watsonx") wrapping a prepared AsyncOpenAI — not LiteLLM. Conservative profile via get_model_profile (§7.2); watsonx ids are not GPT names.

IAM tokens last ~1h. Cache by API key, refresh ~60s before expiry, share one exchange across concurrent requests. This is the only backend where LCORE must manage short-lived tokens (Azure Entra / Vertex ADC / Bedrock SigV4 refresh inside their SDKs). 

IAM_TOKEN_URL = "https://iam.cloud.ibm.com/identity/token"
IAM_GRANT = "urn:ibm:params:oauth:grant-type:apikey"
SKEW_SECONDS = 60

async def exchange_iam_token(api_key: str) -> tuple[str, float]:
    async with httpx.AsyncClient() as http:
        resp = await http.post(
            IAM_TOKEN_URL,
            headers={"Content-Type": "application/x-www-form-urlencoded"},
            content=f"grant_type={IAM_GRANT}&apikey={api_key}",
            timeout=30,
        )
        resp.raise_for_status()
        data = resp.json()
        return data["access_token"], float(data.get("expiration", time.time() + 3600))


async def get_iam_token(api_key: str, cache: dict) -> str:
    cached = cache.get(api_key)
    if cached and time.time() < cached[1] - SKEW_SECONDS:
        return cached[0]
    token, expires_at = await exchange_iam_token(api_key)
    cache[api_key] = (token, expires_at)
    return token


class WatsonxIAMAuth(httpx.Auth):
    def __init__(self, api_key: str, iam_cache: dict) -> None:
        self.api_key, self.iam_cache = api_key, iam_cache

    async def async_auth_flow(self, request: httpx.Request):
        token = await get_iam_token(self.api_key, self.iam_cache)
        request.headers["Authorization"] = f"Bearer {token}"
        yield request
Preferred: build the client once in _build_client (Final[_client]). Inject Bearer per request via WatsonxIAMAuth — same idea as Azure’s token-provider. Do not rebuild the client on IAM refresh. 
# WatsonxInferenceProvider._build_client — once at boot

    api_key="unused",
    base_url=f"{config.base_url.rstrip('/')}/ml/v1",

7. Profiles and settings

Single place for “what can this model do?” and “what do we actually send?”. HTTP adapters echo the resolver; they do not keep a second capability table.

7.1 Every Model has a profile

PAI Model.profile is never missing. Construction merges (later wins):

  1. DEFAULT_PROFILE (PAI conservative baseline)
  2. provider.model_profile(model_name) when implemented
  3. optional constructor profile= (LCORE overlay)

OpenAI / Azure use openai_model_profile — a GPT table, not a probe; unrecognized names still get supports_json_schema_output=True. Vertex and Bedrock ship native tables. Do not fork those tables into LCORE.

7.2 get_model_profile

One method on every InferenceProvider, always a concrete ModelProfile. Callers do not branch native vs custom after this. build_model passes the same dict as constructor profile=.

profile = provider.get_model_profile(model_name) │ ├── base │ native: merge(DEFAULT_PROFILE, SDK.model_profile(name)) │ watsonx/vllm: bundled models.json[name] │ else CONSERVATIVE_OPENAI_COMPAT │ └── operator overlay (optional) entry.model_profiles_path JSON [name] # one file per provider │ ▼ resolve_model_settings(profile, requested) → applied + warnings | 400 │ ▼ Agent.run(..., model_settings=applied)

Lookup is exact model_name (optional longest-prefix later). Miss in JSON is not a 400 — allowed_models already gated the catalog. JSON is booleans and small strings only (no Python classes), validated against a fixed schema. Conservative OpenAI-compat default: tools on if the backend exposes them; JSON schema / object / image / parallel / hosted native tools off unless an entry enables them.

Operator file — one per provider entry. Optional model_profiles_path on the entry points at a JSON object keyed by model id. Loaded once at provider create(). Same schema as bundled models.json. Merged on top of the base profile so deployers can override defaults without a code change. Prefer this over a single global profiles file (keeps each provider’s overrides next to that deployment). Native backends may use the same knob; usually unnecessary when PAI’s table is enough. 

{
  "granite-3.3-8b-instruct": {
    "supports_tools": true,
    "openai_chat_thinking_field": "reasoning",
    "openai_chat_supports_multiple_system_messages": false
  },
  "meta-llama/llama-3-3-70b-instruct": {
    "supports_tools": true,
    "supports_json_object_output": true
  }
}
WatsonxProvider / VllmProvider subclass Provider[AsyncOpenAI] (or override model_profile to None). Do not inherit OpenAIProvider.model_profile — that would still run the GPT table in merge step 2 and claim JSON schema for Granite / Llama ids. Ship optional bundled defaults next to the module; operator overlays live only via model_profiles_path.

7.3 Resolve-then-echo

After §7.2 the helper turns profile + request settings into ModelSettings for Agent.run. It does not look up JSON or call the SDK again.

  1. Accept schema-valid settings — do not 400 because a backend “usually ignores” a field.
  2. Resolve against the profile: drop or coerce so the call can start (drop parallel_tool_calls when unsupported; map OpenAI thinking to Vertex thinking_config or drop; do not send JSON-schema output_type when the flag is false).
  3. Echo the applied dict, not the raw request.
  4. Warn on every drop or coercion (log + structured warning for the adapter).
  5. 400 only for output contract (client required JSON schema the profile cannot honor) or cannot start (missing credentials, unknown model, empty messages).
Avoid: catching PAI UserError / vendor 400s as a capability probe. Read profile flags first; do not send the option. Host 4xx after a conservative profile are then real transport errors.

Maps that are not profile booleans live here: parallel_tool_calls (OpenAI/Azure; omit on Bedrock/Vertex unless the profile says otherwise); thinking / reasoning effort (OpenAI vs Vertex thinking_config vs Bedrock extras); extra body (WatsonX project_id, vLLM passthrough). Native tool-choice is a profile flag the agent path reads — not an HTTP adapter special case. 

provider = registry.get(provider_id)
profile = provider.get_model_profile(model_name)
model = provider.build_model(model_name)
resolved = resolve_model_settings(profile, requested)
# resolved.applied → Agent.run; resolved.warnings → echo (Responses)
# resolved.error → 400 output-contract | cannot-start

Query, streaming query, and Responses all use this path. Only Responses must echo applied on the public object.

8. Catalog endpoints

Today GET /v1/models and GET /v1/providers ask OGX. After cutover LCORE does the same job: discover from each configured provider, filter with allowed_models, cache, serve. Keep the public ModelsResponse / CatalogModel shape.

Policy:
  • Catalog filled once inside each provider’s create() at startup — not on every GET
  • allowed_models is None → keep all discovered ids
  • list → keep discovered ∩ allowed only
  • allowed id missing from discovery → warn and omit (not listed on GET /v1/models, not accepted by get_model); do not fail boot
  • Cloud invoke permissions are out of scope. Operators own IAM / Bedrock model access / project quotas

8.1 When to apply allowed_models

Vendor discovery and the allow-list are separate ideas. Two places we could enforce the list:

  • A — List all discovered; gate only at request time. GET /v1/models shows every id the vendor returned. allowed_models is checked only when building a model for Query / Responses. Good for operators copying ids into config; bad for clients, who treat the models endpoint as a picker and would see options that later fail.
  • B — Filter the catalog at startup (preferred). Cache = discovered ∩ allowed (or all discovered when allowed is None). Same cache for GET /v1/models and get_model. The public list means “what this deployment will serve,” not “what the vendor knows about.”
Choose B. LCORE’s models endpoint is the usable catalog for UIs and callers. One cache avoids “listed but forbidden.” Operators who need a raw inventory can set allowed_models: null temporarily, or use vendor consoles / logs — not the public contract.

8.2 Discover, then filter

Done inside InferenceProvider._load_model_catalog during create() (§5.2):

  1. _discover_models_or_fallback — vendor list, or empty list on failure (log error; do not invent ids from config)
  2. _apply_allowed_models_filter — None keeps all discovered; a list keeps only ids present in both. Missing allowed ids → warn and omit (not in catalog / models endpoint)
  3. _to_catalog_models — map to public CatalogModel rows and cache on _models / _model_ids
@dataclass
class DiscoveredModel:
    id: str
    metadata: dict[str, Any] = field(default_factory=dict)

After create(), that cache is the only source for accepts_model, build_model, and list_models. Configured-but-unresolved models never appear there. Discovery failure still does not crash the process.

No unified SDK list_models. Each subclass uses its cached client (Bedrock: control-plane sibling).
